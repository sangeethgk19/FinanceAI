5
Build the FastAPI — create the door
Wrap your model so anything can talk to it
Week 1
🎓 Teacher says
Now create a new file called api.py. This file creates a web server with one job — receive a question and a model name, ask that model, return the answer. This is the backbone of your whole system. Everything else connects to this.
# api.py
from fastapi import FastAPI
from pydantic import BaseModel
import ollama, time

app = FastAPI()

class Question(BaseModel):
  text: str
  model: str

@app.post("/ask")
def ask(q: Question):
  start = time.time()
  response = ollama.chat(
    model=q.model,
    messages=[{"role":"user","content":q.text}]
  )
  duration = time.time() - start
  answer = response["message"]["content"]
  return {"answer": answer, "seconds": duration}

# Run with: uvicorn api:app --reload
✅ You're done with this step when:
You run uvicorn api:app --reload, open your browser at localhost:8000/docs, and see a test page where you can type a question, pick a model, and get an answer back with a time in seconds.

📊 Part 4 — The Benchmarking (Your Research)
7
Write your 20 test questions
This is your evaluation dataset — treat it carefully
Week 2
🎓 Teacher says
You need 20 questions that cover different types of tasks. Don't just write 20 easy factual questions — mix it up. Cover four categories, five questions each. Write these in a plain Python list in a file called questions.py.
Category 1 — Factual (5 questions)
e.g. "What is the capital of Australia?" Simple questions with one correct answer. Easy to mark right or wrong.
Category 2 — Reasoning (5 questions)
e.g. "If a train travels 60mph for 2 hours, how far does it go?" Tests logical thinking, not just memory.
Category 3 — Summarisation (5 questions)
e.g. Give a paragraph of text and ask "Summarise this in two sentences." Tests writing and comprehension.
Category 4 — Practical/advice (5 questions)
e.g. "What are three ways to reduce stress?" Tests usefulness and common sense reasoning.
✅ You're done with this step when:
You have a Python list of exactly 20 questions, 5 from each category, saved in questions.py.
8
Run the benchmark script — collect all results
60 answers total — 20 questions × 3 models
Week 3
🎓 Teacher says
Create a file called benchmark.py. This script loops through every model and every question automatically, records the results, and saves everything to a CSV file. Run this once and leave it — it will take about 20–30 minutes to complete all 60 answers. Go make a cup of tea.
# benchmark.py
import requests, time, pandas, psutil
from questions import questions

models = ["mistral", "llama3.2", "phi3:mini"]
results = []

for model in models:
  for q in questions:
    ram_before = psutil.virtual_memory().used
    start = time.time()
    r = requests.post("http://localhost:8000/ask",
      json={"text":q, "model":model}).json()
    duration = time.time() - start
    ram_used = psutil.virtual_memory().used - ram_before
    results.append({
      "model": model,
      "question": q,
      "answer": r["answer"],
      "seconds": duration,
      "ram_mb": ram_used / 1024 / 1024
    })
    print(f"Done: {model} — {q[:30]}...")

pandas.DataFrame(results).to_csv("results.csv", index=False)
print("All done! results.csv saved.")
✅ You're done with this step when:
You have a results.csv file with 60 rows. Open it in Excel and you should see every question, every model, every answer, every time, and every RAM reading.

# Add this below your existing app.py chat section
import pandas as pd
import plotly.express as px

st.divider()
st.subheader("📊 Benchmark Results")

df = pd.read_csv("results_scored.csv")
avg = df.groupby("model").mean(numeric_only=True).reset_index()

# Chart 1: Speed
fig1 = px.bar(avg, x="model", y="seconds",
  title="Average Response Time (lower = faster)",
  color="model")
st.plotly_chart(fig1)

# Chart 2: Quality
fig2 = px.bar(avg, x="model", y="quality_score",
  title="Average Quality Score (higher = better)",
  color="model")
st.plotly_chart(fig2)

# Chart 3: Speed vs Quality tradeoff
fig3 = px.scatter(avg, x="seconds", y="quality_score",
  text="model", title="Speed vs Quality Tradeoff")
st.plotly_chart(fig3)

Numbers alone don't make a dissertation. You need to interpret what they mean. For each scenario below, look at your actual results and write 2–3 sentences recommending a model and explaining why using your data. This section is what separates a good dissertation from an average one.
